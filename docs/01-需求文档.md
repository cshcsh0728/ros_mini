## 1 项目概述

### 1.1 背景

ROS（Robot Operating System）是机器人领域主流的分布式通信框架。其核心并非某个具体算法，而是“节点—话题”的松耦合发布/订阅通信模式：系统中的每个功能模块被封装为节点（Node），节点之间不直接互相调用，而是通过话题（Topic）交换消息（Message），由此实现多模块协同工作。

本次大作业不要求接入真实 ROS 运行时，也不要求使用 roscpp 等官方 API，而是使用标准 C++ 在**单进程内**复现上述通信逻辑。考察重点为：面向对象抽象能力、STL 容器使用、对象生命周期管理、异常处理设计，以及工程化能力（版本控制、文档、测试）。

### 1.2 目标

| 编号 | 目标 |
|---|---|
| G1 | 使用 C++17 实现一个可在单进程内运行的最小发布/订阅通信框架 |
| G2 | 以抽象基类 + 多态统一节点行为，以单例集中管理全局通信状态 |
| G3 | 建立明确的异常语义，保证任何非法输入均不导致进程崩溃 |
| G4 | 交付需求、架构设计、技术、用户手册四份文档，以及可重复执行的测试用例 |
| G5 | 通过 Git 增量提交，完整、可追溯地记录开发过程 |

## 2 术语与缩略语

| 术语 | 英文 | 定义 |
|---|---|---|
| 节点 | Node | 系统的最小功能单元，分为发布者节点与订阅者节点，每个节点拥有唯一名称 |
| 话题 | Topic | 节点间通信的“通道”，发布者向话题发布消息，订阅者从话题接收消息 |
| 消息 | Message | 通信的数据载体，包含业务内容与生成时间戳 |
| 发布者 | Publisher | 向指定话题发布消息的节点 |
| 订阅者 | Subscriber | 订阅指定话题并接收消息的节点 |
| 核心管理模块 | ROS | 维护话题与节点映射关系、负责消息转发的单例模块 |
| 单例模式 | Singleton | 保证某个类在进程内仅存在一个实例的设计模式 |
| 生命周期 | Lifecycle | 节点从初始化、参与通信到关闭的完整过程 |

### 3.2 关键需求说明

#### 3.2.1 节点（FR-01、FR-02、FR-13）

- 节点类为抽象基类，不允许被直接实例化；
- 构造时必须提供节点名称，名称应满足：非空、去除首尾空白后非空、在核心模块中全局唯一；
- 名称对外仅提供只读访问接口，任何外部代码不得修改；
- 必须定义初始化接口与关闭接口，二者均为纯虚函数，由子类给出具体实现；
- 子类在实现初始化与关闭接口时，必须输出语义明确的日志。

#### 3.2.2 发布者（FR-03、FR-05）

- 除节点名称外，发布者还需持有话题名称，并提供只读访问接口；
- 初始化时：输出初始化日志 → 向核心模块注册自身（以话题名为键）；
- 发布时：接收一段传感器字符串（如 `"temperature=25.3"`）→ 创建消息对象 → 输出发布日志（含话题名与消息内容）→ 将消息交由核心模块按话题转发；
- 发布过程**不等待订阅者响应**，发布者无需感知订阅者数量与存在性，体现松耦合。

#### 3.2.3 订阅者（FR-06、FR-07）

- 与发布者对称，持有话题名称并提供只读访问接口；
- 初始化时输出日志并向核心模块注册自身；
- 接收消息时：输出包含**消息内容**与**消息时间戳**的接收日志，完成被动接收；
- 订阅者不主动拉取消息，消息到达由核心模块推送触发。

#### 3.2.4 消息（FR-04）

- 消息包含两部分：字符串类型的业务内容、生成时刻的系统时间戳；
- 时间戳由消息构造时自动生成，格式固定为 `YYYY-MM-DD HH:MM:SS`（月、日、时、分、秒均补零至两位）；
- 消息对象一旦创建即不可修改，仅提供读取内容与读取时间戳的公有接口，不提供任何写接口；
- 消息内容为空（或仅含空白字符）时视为非法，须抛出异常。

#### 3.2.5 核心管理模块（FR-08、FR-09、FR-10、FR-11）

- 采用单例模式，保证进程内唯一实例，禁止拷贝构造与赋值；
- 维护两张映射表：话题 → 发布者列表、话题 → 订阅者列表；
- 提供发布者注册、订阅者注册接口，注册时更新映射表并校验节点名称唯一性；
- 消息转发：根据话题名查找订阅者列表，将消息推送给该话题下的**每一个**订阅者；
- 转发到不存在的话题时，视为非法操作，抛出异常；
- 统一关闭：遍历所有已注册节点，依次调用其关闭接口，输出全局关闭日志。

#### 3.2.6 多对多通信（FR-11）

- 允许同一话题存在多个发布者与多个订阅者；
- 任一发布者发布的消息，该话题下所有订阅者均应收到；
- 订阅者只接收其订阅话题的消息，不接收其他话题的消息。

#### 3.2.7 异常保护（FR-12）

- 所有对外接口在入口处完成参数校验；
- 校验失败时抛出携带明确语义的异常对象，异常信息应说明“哪个参数、什么错误、期望是什么”；
- 演示程序须捕获异常并输出提示后继续运行，不允许因未捕获异常导致进程终止；
- 详细异常场景见第 5 节。

### 3.3 典型业务流程

以“一个发布者向话题 `sensor` 发布一条温度数据，两个订阅者接收”为例：

```
Publisher::publish("temperature=25.3")
        │
        │ 1. 创建 Message（自动生成时间戳）
        ▼
   ROS::publish("sensor", msg)
        │
        │ 2. 查表 subs_["sensor"]
        ├──────────────► SubscriberA::receive(msg)  → 打印 [接收] 内容 + 时间戳
        └──────────────► SubscriberB::receive(msg)  → 打印 [接收] 内容 + 时间戳
```

对应步骤说明：

1. 发布者校验内容非空，创建消息对象；
2. 发布者输出发布日志，并将消息交给核心模块；
3. 核心模块以话题名为键查找订阅者列表；
4. 核心模块依次调用每个订阅者的接收接口；
5. 订阅者输出接收日志，流程结束（发布者不等待、不感知结果）。

### 3.4 生命周期约束

任一节点的完整生命周期为：**构造 → 初始化（注册） → 参与通信 → 关闭（注销） → 析构**。

- 未初始化即参与通信属非法操作；
- 关闭后不得再参与通信；
- 核心模块统一关闭时，须保证每个节点仅被关闭一次。

## 4 非功能需求

| 编号 | 类别 | 要求 | 验收方式 |
|---|---|---|---|
| NFR-01 | 编码规范 | 使用 C++17；4 空格缩进；源文件 UTF-8 编码；类名 PascalCase、函数名 camelCase、成员变量以 `_` 结尾 | 代码走查 |
| NFR-02 | 可维护性 | 单一职责；核心模块依赖抽象基类而非具体类型；新增节点类型无需修改核心模块 | 代码走查 + 扩展试验 |
| NFR-03 | 健壮性 | 所有公有接口校验入参；异常信息包含具体原因；无内存泄漏与悬空指针 | 异常用例测试 |
| NFR-04 | 可测试性 | 核心逻辑与 `main` 解耦，可被测试程序直接调用；测试覆盖正常、边界、异常三类场景 | 测试用例表 + 执行结果 |
| NFR-05 | 可读性 | 关键类、关键算法有注释；日志格式统一，含时间戳与节点名 | 代码走查 |
| NFR-06 | 可移植性 | 仅使用标准 C++ 与标准库，不依赖平台专有 API，不使用 `#pragma once` 以外的编译器扩展 | 代码走查：头文件与 API 均来自标准库 |
| NFR-07 | 可追溯性 | 每个功能点对应一次或多次 Git 提交，提交信息遵循约定式格式 | `git log` 检查 |

## 5 异常场景定义

| 编号 | 场景 | 触发条件 | 期望行为 | 异常类型 |
|---|---|---|---|---|
| EX-01 | 空节点名 | 构造节点时传入空串或纯空白 | 拒绝构造，抛出异常，提示节点名不可为空 | `NodeException` |
| EX-02 | 重复节点注册 | 注册的节点名称已存在于核心模块 | 拒绝注册，抛出异常，提示名称重复 | `NodeException` |
| EX-03 | 空消息内容 | 构造消息或发布时内容为空/纯空白 | 拒绝创建，抛出异常 | `MessageException` |
| EX-04 | 话题不存在 | 向核心模块转发一个未注册的话题 | 拒绝转发，抛出异常，提示话题不存在 | `TopicException` |
| EX-05 | 空话题名 | 构造发布者/订阅者时话题名为空 | 拒绝构造，抛出异常 | `TopicException` |
| EX-06 | 关闭后继续通信 | 节点已关闭仍尝试发布或接收 | 拒绝操作并记录 WARN 日志 | `NodeException` |

异常信息示例（要求包含主体与原因）：

```
[NodeException] 节点名不能为空：节点名去除空白后长度为 0
[NodeException] 节点注册失败：名称 "pub_a" 已被占用
[MessageException] 消息内容不能为空：内容长度为 0
[TopicException] 话题不存在："sensor_x" 尚未注册任何订阅者
```

## 6 验收标准

### 6.1 功能验收

- [ ] 可成功创建 1 个发布者与 1 个订阅者，消息能被接收并打印内容与时间戳
- [ ] 可创建 2 个发布者与 2 个订阅者，同一话题下所有订阅者均收到全部消息
- [ ] 订阅者不接收未订阅话题的消息
- [ ] 消息时间戳格式为 `YYYY-MM-DD HH:MM:SS`，且各字段补零
- [ ] 消息对象对外只读，无法通过公有接口修改内容与时间戳
- [ ] 节点名称对外只读，无法被外部修改
- [ ] 节点初始化、发布、接收、关闭各环节均有日志输出
- [ ] 调用统一关闭接口后，所有节点均输出关闭日志，且各关闭一次

### 6.2 异常验收

- [ ] 传入空节点名 → 抛出异常，进程不崩溃
- [ ] 注册重复节点名 → 抛出异常，进程不崩溃
- [ ] 发布空消息 → 抛出异常，进程不崩溃
- [ ] 向不存在的话题发布 → 抛出异常，进程不崩溃
- [ ] 异常信息可读，能定位到具体参数与原因

### 6.3 工程验收

- [ ] 可通过 CMake 一条命令完成配置与构建，无编译警告（或已说明的例外）
- [ ] 测试程序可独立运行，覆盖正常、边界、异常三类场景
- [ ] Git 提交为增量式，每个功能点对应独立提交，信息语义明确
- [ ] 四份文档齐全：需求、架构设计、技术、用户手册
